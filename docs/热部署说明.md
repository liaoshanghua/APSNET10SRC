# APS 热部署（准零停机）

后端 DLL 变更必须短暂停服；本方案把停服时间压到约 **10～30 秒**，并尽量自动化。

## 文件

| 文件 | 位置 | 作用 |
|------|------|------|
| `Publish-Aps-HotDeploy.ps1` | `scripts/` | 开发机：发布 + 同步到服务器 `update\` |
| `Apply-ApsHotUpdate.ps1` | 发布目录根 | 服务器：停服 → 覆盖 → 启动 |
| `APS-热更新.bat` | 发布目录根 | 双击执行热更新 |

**不会覆盖**：`appsettings.json`、`register.ini`、`logs\`

## 方式一：开发机发布 + 服务器手动热更新（推荐）

### 1. 开发机

```powershell
cd EasyManufacture.Net10

# 将 publish 同步到服务器 APS 目录下的 update 子文件夹
.\scripts\Publish-Aps-HotDeploy.ps1 -TargetPath "\\192.168.1.88\APSNEW"
# 本机测试：-TargetPath "D:\APSNEW"
```

### 2. 服务器

进入 APS 安装目录（与 `APS.exe` 同级），双击：

```text
APS-热更新.bat
```

按提示输入 `YES`，脚本会：结束 APS → 用 `update\` 覆盖程序 → 自动启动 → 检查 `/APSAPI/Ping`。

## 方式二：在服务器上一键发布并热更新

在**服务器**上拉取代码或已有 publish 时：

```powershell
cd EasyManufacture.Net10

.\scripts\Publish-Aps-HotDeploy.ps1 `
  -TargetPath "D:\APSNEW" `
  -RunHotUpdate `
  -Confirm
```

## 方式三：只更新前端（不停服）

仅 `wwwroot` 变更时，可直接覆盖，无需热更新脚本：

```powershell
robocopy .\publish\api\wwwroot D:\APSNEW\wwwroot /E /IS /IT
```

## 常用参数

`Publish-Aps-HotDeploy.ps1`：

| 参数 | 说明 |
|------|------|
| `-TargetPath` | APS 安装目录（必填） |
| `-RunHotUpdate` | 同步后立即执行热更新（须在能访问该路径的机器上运行） |
| `-SkipPublish` | 不重新 publish，只用已有 `publish\api` |
| `-Backup` | 热更新前备份 exe/dll 到 `backup\时间戳\` |
| `-NoStart` | 只覆盖文件，不自动启动 |
| `-Confirm` | 跳过 YES 确认 |

## 日志

热更新日志：`logs\hot-update.log`

## 注意

1. `update\` 里的 `.bak` 路径、数据库连接等**不会**自动改服务器配置。  
2. 从开发机 `-RunHotUpdate` 远程杀进程**不可靠**（进程在服务器上）；远程共享请用方式一，在服务器点 `APS-热更新.bat`。  
3. 若 Ping 检查失败，查看 `logs\aps-console.log`。
